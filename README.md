# Jewelry AI Studio

面向珠宝商家的视觉策略 MVP。用户上传 1–3 张产品图和已核实资料，服务端调用 OpenAI Responses API 完成多模态分析，输出：

- 产品事实卡：区分用户提供、图片可见和仍需核实的信息；
- 视觉诊断：有效之处、关键问题和第一优先级；
- 创意方向：概念、配色、搭配、光线与背景；
- 拍摄执行单、内容角度、建议交付和人工复核项；
- 可下载的 Markdown 方案。

没有上传图片或没有配置 AI 服务时，页面会明确显示“规则预览”，不会把规则结果伪装成图像分析。

## 本地运行

需要 Node.js 20+ 与 pnpm。

1. 执行 `pnpm install --frozen-lockfile`。
2. 复制 `.env.example` 为 `.env.local`，填写服务器端 `OPENAI_API_KEY`。密钥不得写入前端变量或提交到 Git。
3. 可通过 `OPENAI_VISION_MODEL` 更换支持图像输入和结构化输出的模型；默认是 `gpt-6.1-terra`。
4. 执行 `pnpm dev`。

运行 `pnpm test` 检查输入限制、事实边界和规则逻辑；运行 `pnpm build` 验证生产构建。

## API

`POST /api/diagnose` 接受 `multipart/form-data`：产品名、品类、材质、场景、渠道、目标、问题、客群，以及名为 `images` 的 1–3 张图片。

- 支持 JPG、PNG、WebP；单张不超过 6MB，总计不超过 12MB。
- API 密钥只在服务端读取。
- 请求使用结构化 JSON Schema；模型结果会把图片可见事实与未知信息分开。
- 请求设置 `store: false`。生产环境仍应补充用户授权说明、用量限制、身份验证和日志脱敏。

## 事实边界

系统不会仅凭图片判断宝石真伪、天然或合成、具体材质、克重、尺寸、证书、品牌和价格。材质、工艺、尺寸与证书必须由商家或鉴定资料确认。红、黄、绿三组预设仅用于演示，不是真实客户案例。

## 部署

仓库没有 `.openai/hosting.json` 时，构建会跳过 Sites 元数据复制。部署到既有 Sites 项目时，应保留该项目的 hosting manifest 和项目身份，并在部署平台配置 `OPENAI_API_KEY`。不要将密钥写入 `.env.example` 或源代码。

## 进入可收费版本前

用三件真实珠宝完成“上传—AI 方案—人工修订—实际制作—客户反馈—成本记录”，再增加账户、项目保存、额度、订单和图像生成。当前版本聚焦最关键的产品价值：把一张珠宝图转换为可审核、可执行的视觉策略。
